SST — Red: notsh / net

1. Nombres y rutas equivalentes

Comando principal:
  notsh SUBCOMANDO ...

Alias completo:
  net SUBCOMANDO ...

Compatibilidad de contextos Windows:
  notsh lan show interfaces       estado físico/IP y datos Dot3 disponibles; no certifica autorización NAC
  notsh lan show profiles         perfiles de Wired AutoConfig
  notsh wlan show interfaces      estado Wi-Fi/SSID/autenticación mediante API WLAN
  notsh wlan show profiles        perfiles WLAN
  notsh wlan show networks        redes WLAN observadas
  notsh interface ipv4 show interfaces
  notsh interface ipv6 show interfaces

Los contextos NOTSH usan las API nativas correspondientes (IP Helper, Dot3, WLAN, WinHTTP, Winsock, Firewall y HTTP.sys). Las operaciones avanzadas no implementadas devuelven error; no se ofrece lan show settings como función disponible.

Sin argumentos:
  notsh     muestra el índice de comandos
  net       mismo índice (alias)

2. Interfaces nativas de SST
  notsh interfaces       todos los adaptadores IP Helper
  notsh show interfaces  vista general propia de SST
  notsh link             interfaces y enlace
  notsh addr             interfaces y dirección IP
3. Conexiones

  net connections
  notsh ss
  notsh socket
  notsh sockets

Muestra protocolo, local, remoto, estado y PID propietario.

4. Rutas

  net routes
  notsh route

Muestra la tabla de rutas reportada por la sonda nativa de red de SST.

5. Vecinos / ARP

  net neighbors
  net arp
  notsh neigh
  notsh neighbor

Muestra IP, MAC, tipo de MAC y fabricante cuando puede atribuir OUI.

6. DNS

  net dns HOST
  net dns IP
  net resolve HOST
  net resolve IP

HOST:
  resolución directa; deduplica y ordena direcciones devueltas.

IP:
  resolución inversa; si no existe nombre devuelve `-`.

No hay flags adicionales implementados para dns.

7. Ping ICMP

  net ping HOST
  net ping HOST -c N

Opciones:
  -c N  cantidad de ecos.

Default:
  N=4

Rango:
  1..100

Cada eco usa TTL 128 y timeout de 1 segundo. El comando devuelve status 0 si recibe al menos una respuesta y 1 si no recibe ninguna.

8. Traceroute ICMP

  net trace HOST
  net traceroute HOST

Alias:
  traceroute = trace

No tiene flags adicionales. SST prueba TTL 1..30 con timeout aproximado de 700 ms por salto y devuelve status 0 solo si llega al destino.

9. Conflictos IPv4

Aliases equivalentes:
  net conflict
  net conflicts
  net duplicate-ip
  net duplicates

Formas:
  net conflicts
  net conflicts IP
  net conflicts --seconds N
  net conflicts -s N
  net conflicts IP --seconds N
  net conflicts IP -s N
  net conflicts --json
  net conflicts IP --json

Opciones:
  --seconds N
  -s N
    duración de observación.

  --json
    salida JSON.

Default:
  ventana = 5 segundos

Rango:
  1..30 segundos

Sin IP:
  muestrea repetidamente la tabla ARP completa.

Con IP:
  usa resolución activa de vecino/SendARP repetida para esa IPv4.

Conflicto:
  una misma IPv4 observada con dos o más MAC distintas dentro de la ventana.

Status:
  0  no se observó conflicto durante la ventana
  1  se observó al menos un conflicto

Una ejecución sin hallazgos no demuestra ausencia de duplicidad: una caché estable puede ocultar al segundo equipo.

10. Puertos TCP

  net ports HOST
  net ports HOST LISTA

LISTA:
  puertos separados por coma.

Ejemplo:
  net ports servidor 22,80,443,3389

Default si se omite LISTA:
  22,80,443,445,3389

Cada puerto usa connect TCP con timeout aproximado de 500 ms y se muestra como:
  open
  closed/filtered

Valores no parseables dentro de LISTA se descartan silenciosamente por la implementación actual.

11. Escaneo IPv4

  net scan
  net scan RED

Filtros:
  --unknown
    conserva solo no inventariados.

  --authorized
    conserva conocidos/inventariados.

  --known
    alias funcional de --authorized.

Salida/nombres:
  --names
    imprime solo IP y nombre mostrado.

  --json
    salida JSON completa.

  --csv
    salida CSV completa.

Prioridad de salida:
  --json se procesa antes que --names/--csv.
  --names se procesa antes que --csv.

Sin RED:
  SST intenta inferir la red IPv4 local.

Límite de seguridad:
  solo /20 o prefijos más específicos (/21, /24, etc.). Redes mayores que /20 se rechazan.

Métodos de detección usados por la sonda de hosts:
  ARP
  ICMP
  TCP 445
  TCP 3389
  TCP 80
  TCP 443
  TCP 135
  TCP 22

El barrido trabaja por lotes de hasta 48 hosts concurrentes y usa timeout aproximado de 300 ms por prueba primaria.

12. Monitor de presencia/chat LAN

Formas:
  net monitor
  net monitor RED
  net monitor [RED] --unknown
  net monitor [RED] -m TEXTO
  net monitor [RED] --message TEXTO
  net monitor [RED] --say TEXTO

Opciones:
  --unknown
    muestra solo dispositivos no inventariados.

  -m TEXTO
  --message TEXTO
  --say TEXTO
    formas equivalentes para arrancar publicando un mensaje inicial.

RED:
  opcional; si falta SST infiere la red local.
  debe ser /20 o más pequeña.

Opciones desconocidas se rechazan. Más de una RED/argumento posicional inesperado también se rechaza.

Mensaje inicial:
  no puede quedar vacío después de sanitización.

Teclas fuera del prompt:
  Enter       abre `Mensaje>`
  q           salir
  Esc         salir

Teclas dentro del prompt:
  Enter       enviar/ejecutar comando de chat
  Esc         cancelar edición
  Backspace   borrar
  Space       insertar espacio
  caracteres  añadir texto

Límite del input interactivo:
  120 caracteres.

Ciclo:
  SST vuelve a escanear aproximadamente cada 3 segundos.
  un equipo debe faltar 3 escaneos consecutivos antes de marcarse offline.

Comandos del chat:
  ::help
  ::whoisalive
  ::room NOMBRE [CLAVE]
  ::join NOMBRE [CLAVE]
  ::leave
  ::where
  ::rooms
  ::pm IP MENSAJE
  ::fingerprint
  ::lore
  ::peers
  ::clear

Detalles:
  ::room y ::join son equivalentes.
  CLAVE puede contener espacios; se deriva sobre el texto restante.
  salas con CLAVE usan Argon2id + XChaCha20-Poly1305.
  ::pm usa X25519 + XChaCha20-Poly1305.
  antes de PM el peer debe conocerse; `::whoisalive` ayuda a descubrir identidades.
  ::fingerprint muestra fingerprint criptográfico local.
  ::peers lista terminales SST con identidad conocida.
  ::clear limpia mensajes visibles, no el lore de sesión.
  ::lore guarda el historial de mensajes de la sesión en el directorio actual con nombre `sst-net-monitor-lore-YYYYMMDD-HHMMSS.txt`.

13. Historial persistente de presencia

  net presence
  net presence --json
  net presence --csv

Sin flags:
  tabla ordenada por `last_seen` descendente.

JSON:
  serializa registros completos.

CSV:
  columnas mac,ip,hostname,mac_scope,vendor,discovery,first_seen,last_seen.

No hay otros filtros implementados en `presence`.

14. Identificación

  net identify IP
  net identify MAC
  net identify NOMBRE
  net identify OBJETIVO --json

OBJETIVO puede ser:
  IPv4
  MAC
  nombre inventariado exacto case-insensitive

Para IP intenta:
  - probe activo
  - ARP
  - reverse DNS
  - historial de presencia

Para MAC/nombre cruza inventario e historial.

Campos:
  target
  ip
  hostname
  mac
  mac_scope
  vendor
  ieee_registry
  inventory / inventory_name
  registered
  discovery
  response
  last_seen

  --json  salida JSON.

No hay otros flags implementados.

15. Tráfico por proceso

Base:
  net traffic

Modo continuo:
  net traffic --watch
  net traffic -w

Filtros/opciones:
  --top N
    máximo de filas en salida de tabla. Default 50.

  --pid PID
    limita al PID parseable indicado.

  --process NOMBRE
    coincidencia substring case-insensitive sobre nombre de proceso.

  --background
    excluye el proceso foreground actual.

  --high-usage
    conserva procesos que superen al menos uno de estos umbrales:
      tráfico combinado >= 100 KiB/s
      CPU >= 10%

  --unsigned
    conserva procesos cuya firma Authenticode no sea `valid`.

  --connections
    cambia a vista de conexiones TCP/UDP por proceso.

  --json
    salida JSON.

  --csv
    salida CSV.

Telemetría:
  intenta ETW para bytes por proceso. Si ETW no está disponible, la vista sigue funcionando con conexiones/CPU/RAM y lo informa.

`--connections`:
  puede combinarse con --pid, --process, --top, --json y --csv.
  en salida textual `--top` limita filas; JSON/CSV devuelven las filas filtradas completas antes del `.take(top)` textual actual.

`--watch`/`-w`:
  refresca aproximadamente cada 1 segundo.
  q o Esc salen.
  los demás filtros se conservan.

16. Consumo LAN por proveedor

Base:
  net usage

Modo continuo:
  net usage --watch
  net usage -w

Filtros:
  --top N
  --device IP
  --mac MAC

Formatos:
  --json
  --csv

`--top` sin un valor siguiente es tolerado por el parser genérico pero no aplica truncado; para limitar filas usa siempre `--top N`.

--watch/-w:
  refresca cada 2 segundos y mantiene los demás filtros.

Requisito:
  debe existir un proveedor activo.

Tipos con obtención de uso implementada hoy:
  openwrt   consume endpoint JSON normalizado configurado en host
  generic   consume endpoint JSON normalizado

Tipos declarados pero que requieren adaptador/MIB específico para uso:
  opnsense
  pfsense
  unifi
  snmp

17. Proveedores

Acción por defecto:
  net provider
  net provider list

Listar:
  net provider list
  net provider list --json

Crear/actualizar:
  net provider add NOMBRE --host HOST
  net provider add NOMBRE --type TIPO --host HOST
  net provider add NOMBRE --host HOST --user-env VAR
  net provider add NOMBRE --host HOST --secret-env VAR
  net provider add NOMBRE --host HOST --community-env VAR
  net provider add NOMBRE --type TIPO --host HOST --user-env VAR --secret-env VAR --community-env VAR

Opciones add:
  --type TIPO
    default: generic

  --host HOST
    obligatorio

  --user-env VAR
    nombre de variable de entorno con usuario HTTP.

  --secret-env VAR
    nombre de variable de entorno con contraseña/token.

  --community-env VAR
    nombre de variable de entorno con community SNMP.

TIPO admitido:
  openwrt
  opnsense
  pfsense
  unifi
  snmp
  generic

Si el perfil ya existe con el mismo nombre, `add` lo actualiza.
El primer proveedor añadido queda activo automáticamente.

Seleccionar activo:
  net provider use NOMBRE

Ver activo:
  net provider current

Eliminar:
  net provider remove NOMBRE

Si se elimina el activo, el primer proveedor restante pasa a activo.

Capacidades:
  net provider capabilities
    usa activo.

  net provider capabilities NOMBRE
    consulta perfil explícito.

Ruta de almacenamiento:
  net provider path

Credenciales HTTP:
  SST toma secretos desde variables de entorno y los pasa a curl mediante config por stdin, evitando poner `user:password` o Bearer token en la línea de comando del proceso curl.

19. notsh test — diagnóstico integral, medidas y tráfico

  notsh test
    Ejecuta el diagnóstico general, medición de tráfico real en interfaces,
    pérdida ICMP contra el gateway predeterminado y breve observación ETW.

  notsh test full HOST
    Realiza pruebas de enlace, IP/APIPA, gateway, NAC/802.1X, DNS, ICMP, TCP,
    velocidad de NIC, pérdida, jitter y tráfico por proceso sobre ese destino.

  notsh test HOST [--port PUERTO]
    Inspección rápida de conectividad y servicio TCP. No mide velocidad.

  notsh test loss [HOST] --count 20 --interval 400 --timeout 800
    Prueba repetida ICMP IPv4 (gateway por defecto cuando se omite HOST).
    Informa enviados, recibidos, pérdidas %, RTT mínimo/medio/máximo,
    variación de RTT y racha máxima de fallos. Errores de API se separan.

  notsh test stability [HOST] --seconds 20 --interval 1000
    Mide disponibilidad y oscilaciones de RTT a lo largo del tiempo.
    Con --tcp PUERTO evalúa disponibilidad TCP (no pérdida de paquetes IP).

  notsh test speed --passive --seconds 4
    Mide con IP Helper los contadores de bytes reales RX/TX de NIC Ethernet
    y Wi-Fi físicas, velocidad de enlace negociado y errores/descartes.
    No equivale a velocidad máxima hacia Internet.

  notsh test speed --download https://SERVIDOR/archivo.bin --seconds 10 --max-mib 64
    Prueba activa de DESCARGA HTTPS con WinHTTP, sin curl.exe ni otros
    ejecutables. Usa un endpoint elegido por el operador, hasta el tiempo
    y volumen máximos indicados, sin guardar los datos descargados.
    El modo activo mide descarga y subida HTTPS con datos sintéticos. Por defecto usa Cloudflare; --download y --upload permiten indicar endpoints compatibles. Los resultados corresponden a los destinos medidos. --passive evita las transferencias de prueba.

  notsh test traffic --seconds 5 [--pid PID] [--top N]
    Captura eventos de red ETW y presenta bytes por segundo TX/RX por proceso,
    nombre de proceso, PID, conexiones activas TCP/UDP, destinos y servicios
    Windows relacionados con ese PID según Service Control Manager.
    Si el proceso aloja múltiples servicios, NO se atribuyen los bytes a uno
    individual: sólo se indica que comparten el proceso.

  notsh test inspect --seconds 5 --pid PID
    Misma observación ETW filtrada al PID, con conexiones y servicios.

  notsh test packets --seconds 5 [--pid PID]
    Muestra eventos individuales de red ETW con dirección TX/RX, bytes,
    PID y código de evento, con cola acotada a 1024 observaciones.
    NO es un sniffer de tramas NDIS ni inspecciona el contenido del payload.

  notsh test capture --interface IPV4_LOCAL --seconds 5 --limit 100
    Captura real de paquetes IPv4 mediante Winsock SOCK_RAW + SIO_RCVALL,
    únicamente para la IPv4 indicada en una interfaz local, sin procesos
    externos, y muestra IP origen/destino, puertos TCP/UDP, flags TCP, bytes,
    dirección TX/RX y servicio probable (inferido del puerto).
    Requiere permiso de Administrador y adaptador/política compatible.
    Sólo recibe tráfico IPv4 hacia/desde la IP de interfaz elegida.

  notsh test capture --interface IPV4_LOCAL --seconds 5 --payload-bytes 32
    Añade el prefijo hexadecimal de hasta 32 bytes de carga útil por paquete
    si el operador lo solicita expresamente. El contenido puede ser sensible.
    El límite es de 64 bytes y nunca se muestra por defecto.
    HTTPS/TLS sigue cifrado. No se reconstruyen sesiones, archivos, imágenes
    ni datos de aplicación; el nombre de servicio inferido no es garantía.

  notsh test --help
    Ayuda de todas las modalidades.

Limitaciones explícitas:
  - Un ICMP perdido puede obedecer a un firewall, no necesariamente a una
    interrupción real del enlace. La ausencia de ICMPv6 se informa.
  - Los contadores de velocidad pasiva indican tráfico actual, no capacidad
    total. La descarga HTTP sí genera tráfico pero sólo al destino elegido.
  - ETW permite contar tráfico por proceso, pero no leer texto, documentos,
    payload ni tráfico TLS descifrado. Para captura real de contenido se
    necesita un controlador NDIS/WFP con autorización; SST no lo suplanta
    ni presenta datos inexistentes.
  - No se modifica la configuración de red ni se exportan credenciales.

21. Regla de exactitud

No se debe inferir soporte por semejanza con netsh/ip/ss. Solo las opciones enumeradas aquí están implementadas por la superficie pública actual de `notsh`/`net`.
